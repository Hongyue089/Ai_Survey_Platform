## 数据关系与工程约定

`t_block.question_groups` 是新增 JSONB NOT NULL 字段，默认 `[]`。组包含 group_id、name、question_ids、question_order、display_mode、display_count。成员必须属于同一个 Block，并由 Service 校验唯一归属和抽取数量。RT 配置属于现有 `t_question.config.response_time`；End Information 属于现有 Flow JSON；无需新增或重建业务表。

组的执行位置是其在 Block 默认顺序中最早成员的位置；组内成员集中展示。Original Order 使用 Question.sort_order；随机抽 N 后仍遵守所选顺序。未分组的问题继续默认顺序。Question Group 抽取和 Flow Randomizer 分配均保存至同一 Session 的 allocations；返回、刷新和同 Session 的再次执行不重新抽取。全新 Session 可产生新结果。随机未展示的问题没有回答，不满足 Branch 的 equals 或 not_equals。

RT 的计时是本次页面呈现到有效操作 / 提交之间的经过时间，返回后的重访独立记录，不覆盖首次记录。后台保留原始事件与两个派生指标。客户端时间可供 Preview 调试，不作为服务端验证 respondent 真实行为的安全证明。

正式 Response / Published Snapshot 仍未设计；没有实现正式发布、正式 respondent 收集或正式 Event Log 表。`block_pages` 为运行时公共分页函数，未来正式 Runtime 应复用同一函数及计时协议。当前已完成 Preview 路径，不能声称正式 Runtime 已完成。

## Windows 更新现有 V2（保留已创建的问卷）

1. 在前后端终端按 Ctrl+C 停止服务，保留 Docker 数据库运行。
2. 将更新包中的源代码覆盖到当前 V2 项目。保留本机 backend/.env、backend/.venv、Git 历史。更新包不包含 .env 或虚拟环境。
3. 在 backend 目录执行：

```powershell
.\.venv\Scripts\python.exe -m app.upgrade
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
```

升级只新增 question_groups 列，可重复执行，不 DROP、不重新 seed、不删除已有问卷。

4. 在 frontend 目录执行：

```powershell
npm ci --include=dev --bin-links=true
npm run dev
```

5. 打开 http://localhost:5173 。关闭之前已经打开的 Preview 页，再从 Builder 创建新 Preview Session，以读取本次修改后的设置。

本次更新不要运行 `app.initialize --reset`，不要执行 `docker compose down -v`。新数据库首次安装仍按 README 的首次安装部分执行。
