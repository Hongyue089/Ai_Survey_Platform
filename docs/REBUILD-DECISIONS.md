# V2 rebuild decisions

Source: Google Doc PRD, revision ANLCKQkuU08BqYQAP7IT435Ti-78wTcUH-t1AlC8l8mUIeom98wTlsNkVmaJreWR5SUX36Cov1T06Qos2QlIXzK5d4jCzMo0FrzbBoivOvg. User amendments on 2026-10-02 override conflicting text.

1. Old archive is inspected only for database reset: its ten mapped business tables are t_user, t_survey, t_survey_members, t_block, t_question, t_survey_flow, t_survey_revision, t_survey_flow_revision, t_ai_config, t_ai_run. No old UI, service, API or type is reused.
2. project_type is canonical at every layer. survey_type is discarded.
3. Flow / Call AI is authoritative: agent_name, input_source_config, max_turns, system_prompt, context_template, user_message_template, temperature, end_condition are separate fields. Supporting runtime/logging fields follow Database Design. Survey has optional default AI config; each Call AI owns a config reference belonging to the same survey.
4. Publish is a disabled visual entry only. Distribution, Analysis and Report have deferred pages. No public runtime, formal Response tables or Published Snapshot are invented.
5. Preview uses an independent temporary PostgreSQL-backed session and a frozen Working Version snapshot. Answers, variables, allocation choices and AI conversation are isolated; formal response_count remains 0. Sessions expire after two hours, are removed at the next Preview start, and survive page refresh/server restart.
6. Builder's explicit autosave section (600 seconds of inactivity) overrides the conflicting 10-second scope summary; Flow uses the same interval, Options uses its explicit 10-second debounce. Autosave and Apply both persist Working Version and append revisions. No autosave-only snapshot behavior.
7. Block delete marks its active questions deleted, retaining original relationships. Individual question restore first restores its original deleted block. Previously independently deleted questions remain deleted. Trash also permits removal of empty deleted blocks, and dependency checks protect Flow/logic references.
8. Branch schema uses condition_groups with stable group IDs, structured per-condition connectors and group connectors; each group has its own children. Group connector combines group predicates. A true compound predicate permits execution of the matching group's path. This resolves the PRD's simultaneous path-per-group and group AND/OR requirements; the explicit JSON schema is documented in API OpenAPI.
9. Randomizer draws without replacement. Even presentation uses counts derived from unexpired Preview sessions under a PostgreSQL advisory transaction lock, isolated to previews; balancing remains Preview-only because no formal respondent storage exists. Back reuses the execution log and allocation rather than rerolling.
10. Unfinished Flow nodes can be stored as drafts; invalid configured Flow fails Preview and never silently falls back. Only a genuinely empty active Flow uses Builder order. AI sources and placeholders are checked against data available on each path.
11. AI calls are server-only using OPENAI_API_KEY; no model name or API key is guessed or embedded. AI_MODEL environment variable supplies default model. No live AI request is made without a configured key. Preview errors follow failure_behavior, never substitute fabricated responses.
12. Current working revisions use optimistic concurrency via working_version. Stable IDs are retained. User ownership and same-survey references are verified server-side. Foreign keys are used for all relational IDs; Flow IDs embedded in JSON are checked in service validation.
13. Old database is on the user's machine and cannot be reached here. The reset CLI inspects actual tables/FKs and verifies schema fingerprint and the development database flag before a transactional reset. It refuses unknown external dependencies and never uses DROP ... CASCADE or deletes unrelated objects.

UI reference images are embedded in the PRD; text extraction alone cannot verify their exact pixels. If their download is blocked, layouts follow the PRD's written geometry and the visual limitation is reported.

14. Preview-only persistence adds t_preview_session. t_ai_conversation/t_ai_run/t_ai_message are preview-linked with real foreign keys; response_id is intentionally deferred until T_response is designed. No unbound response_id foreign key is invented. Flow revisions include an AI configuration snapshot so restoring Flow restores its actual AI settings.
